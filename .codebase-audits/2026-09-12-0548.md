# Codebase Audit — xenon @ 2c9e4d2 — 2026-09-12

## Health summary

Xenon has a credible correctness core: typed identities, strict conditional
publication, pure control transitions, explicit writer fencing, durable operation
replay, broad Temporal semantics, fast Go DST and three real integration journeys.
Its concentrated risk is structural accumulation. A caller can see two runtime
generations, every node drives every physical partition, persistence requests
perform repeated S3 control reads, and the shipping CLI imports its simulation,
integration and proof laboratory. A clean composition rebuild is justified; a
clean-room rewrite of the proven protocols is not.

## Architecture

### H1 — Dual runtime generations remain compiled  `🔴 high · L · CONFIRMED`

**Current:** The supported path constructs `NewServiceRuntime` in
`internal/app/app.go:31`. It uses `cluster`, `partitions`, `persistence` and
`routing`. `internal/app/legacy_storage.go:43` still contains a complete older
composition using `directory`, `ownership` and `node`. Its constructor has no
runtime caller, but both generations register the same twelve persistence services
in `internal/routing/server.go:22-33` and `internal/ownership/rpc.go:27-38`.

**Proposed:** Make format 2 authoritative. Preserve format-1 decoding and fixtures
in an offline compatibility module, and do not port the legacy runtime into the
replacement.

**Why:** Two valid-looking implementations make it easy to change the wrong
generation while still compiling and passing local tests.

**Verification:** `git grep NewLegacyStorageRuntime 2c9e4d2` returned the
definition, one negative unit test and documentation only. Recheck deployment
callers and run retained format-1 fixtures before removal.

### H2 — Per-node control work scales with every partition  `🔴 high · L · CONFIRMED`

**Current:** Every process constructs a `partitions.Service` for every layout
entry at `internal/app/service_runtime.go:133-140` and polls every service at
`internal/app/service_runtime.go:197`, including non-owned partitions.

**Proposed:** Maintain one cluster authority view per node and instantiate local
partition actors only for desired, opening, active, draining or recently lost
partitions.

**Why:** Controller work grows approximately with nodes multiplied by physical
partitions, conflicting with the intended 100-node design ceiling.

**Verification:** Re-read both loops and add a 100-node/high-partition modeled
test measuring controller count, registry operations and steady work per node.

### H3 — Persistence admission performs repeated S3 authority reads  `🔴 high · L · CONFIRMED`

**Current:** `binding.Resolve` calls `b.read` at
`internal/routing/binding.go:77`; local dispatch calls it again at line 115.
`b.read` invokes the registry store, whose production adapter performs S3
`GetObject` at `internal/registry/s3/store.go:53`. A local request needs at least
two control-object reads; a forwarded request needs at least three.

**Proposed:** Centralize control observation into a monotonic local authority
snapshot while retaining fail-closed admission and native writer fencing. Specify
the freshness and final-authority rule before implementation.

**Why:** Data-path latency, availability and S3 cost are unnecessarily coupled to
repeated metadata reads, while authority reasoning is spread across modules.

**Verification:** Preserve stale-owner, ABA, response-loss and post-fence controls;
add assertions that bound control reads per request.

### M1 — Runtime orchestration bypasses virtual time  `🟠 medium · L · CONFIRMED`

**Current:** `cluster.Step` and `partitions.Step` are pure, but
`internal/app/service_runtime.go:142,179,197-244,278-310,334` directly calls
`time.Now`, `time.Since` and `time.NewTicker` for routing, polling, membership and
readiness.

**Proposed:** Run production and DST through the same deterministic node reactor,
with wall-clock and virtual adapters. Keep OS process and uncancelable FFI behavior
in small real-boundary tests.

**Why:** Heartbeat cadence, readiness ordering and shutdown bugs remain outside
the fastest and most controllable test tier.

**Verification:** Search production reactor code for `time.*`; only clock adapters
should retain those calls.

### M2 — Durable contracts lack one compatibility corpus  `🟠 medium · L · CONFIRMED`

**Current:** A narrower stored-data compatibility corpus already exists under
`test/compatibility/rust/` and supports registered compatibility proof. Stable
bytes are nevertheless defined across registry envelopes
(`internal/registry/envelope.go:19`), bootstrap manifests
(`internal/app/bootstrap.go:29`), layout/control codecs
(`internal/cluster/layout.go:14`, `control.go:40`), SlateDB fences
(`internal/partitions/slatedb/engine.go:20`), replay keys
(`internal/persistence/replay.go:30`) and family-specific key/token codecs.

**Proposed:** Freeze a versioned golden corpus for descriptors, envelopes,
layouts, manifests, all durable keys, page tokens, typed errors and outputs.

**Why:** A replacement can pass new behavioral tests while being unable to read
old data or resume old pagination.

**Verification:** Require old-write/new-read and new-write/new-read tests for every
golden vector.

### M3 — Temporal family adapters repeat transport construction  `🟠 medium · M · CONFIRMED`

**Current:** Thirteen production adapter files independently call
`grpc.NewClient` with the same insecure transport and trace interceptor. Family
paths also repeat connection ownership, deterministic marshaling, digest and
operation-envelope work. Retry itself is already centralized in
`internal/temporal/adapter/retry.go`.

**Proposed:** One deep adapter transport owns connection pooling, envelopes,
deadlines, tracing and close lifecycle. Explicit family codecs retain typed
Temporal differences.

**Why:** Transport changes currently touch many files and can drift between
families.

**Verification:** `rg -n 'grpc.NewClient' internal/temporal/adapter` returned 13
production files. Count connections created by a complete factory and run the
pinned adapter suites through the shared transport.

### M4 — Shipping CLI imports the release laboratory  `🟠 medium · M · CONFIRMED`

**Current:** `cmd/xenon/command.go:13-14` imports integration and simulation. Its
dependency closure includes proof packages, and Python-backed smoke profiles remain
in `cmd/xenon/profiles.go:37`. A default arm64 build is 184,167,954 bytes and
`go list -deps ./cmd/xenon` returns 1,748 packages, including 27 local packages.

**Proposed:** Keep one CLI vocabulary but compile product runtime, developer DST
and release laboratory as clean command modules. The distributable runtime should
not include integration, simulation, proof or migration tooling.

**Why:** Users receive historical harness dependencies and two generations of
test workflow in the product executable.

**Verification:** Compare dependency and binary-size reports for the replacement;
map every removed profile assertion to Go or explicit release scope.

## Operations

### M5 — Operator configuration exposes implementation topology  `🟠 medium · M · CONFIRMED`

**Current:** `internal/app/config.go:36` derives ten adjacent service ports.
`internal/app/service_config.go:12` exposes the full immutable layout, seven
timing values, four limits/batches, WAL cadence and retained-outcome capacity.

**Proposed:** Separate a small stable user configuration from advanced tuning.
Derive deterministic internal defaults while preserving explicit correctness and
capacity policy where operators truly need control.

**Why:** Equivalent nodes are easy to misconfigure and upgrades inherit internal
topology as public surface.

**Verification:** Express the current integration deployment with the proposed
minimal config and compare the derived layout/control digest byte-for-byte.

### M6 — Telemetry cannot explain ownership or storage failures  `🟠 medium · M · CONFIRMED`

**Current:** `internal/observability/metrics.go:20` records only fixed routing
attempt counters. `internal/routing/router.go:107` drops events when the channel is
full without a drop counter. The runtime has no coherent structured logger or
ownership, durability, unknown-outcome and partition-phase latency signals.

**Proposed:** Emit bounded typed events at the coordination, partition, routing
and durability seams. Derive low-cardinality metrics, structured logs and traces
without allowing exporters to affect authority or acknowledgement.

**Why:** Current fault diagnosis still depends on retained integration logs and
adding targeted instrumentation after failure.

**Verification:** Inject each named failure family and require one bounded signal
to identify its failing seam; block or fail exporters and prove workflow progress.

### M8 — Owner transport assumes a trusted plaintext network  `🟠 medium · M · CONFIRMED`

**Current:** `internal/routing/router.go:75` creates pooled connections using
`insecure.NewCredentials`; the pool retains up to 64 transient owner addresses.

**Proposed:** Make the trusted-network assumption explicit in the experimental
release. Before claiming untrusted-network support, design authenticated TLS and
node identity binding at this seam.

**Why:** Outside the documented trusted network, an unauthenticated peer could
receive or submit internal persistence traffic.

**Verification:** Inspect deploy documentation and add a configuration rejection
or authenticated transport test before expanding the support claim.

## Documentation and repository structure

### M7 — Current documentation contains demonstrably stale claims  `🟠 medium · S · CONFIRMED`

**Current:** `docs/operations/cli.md:6` says inspect, dev, generated search and
minimize are unimplemented, while `xenon --help` exposes them. `docs/operations.md:78`
and `docs/design/product.md:23` say the repository remains private despite the
recorded public-publication authorization. Some historical documents are clearly
dated and remain valid evidence; they should not be rewritten as current specs.

**Proposed:** Make the replacement dossier the current architecture entrypoint and
mark demonstrably superseded documents with a historical notice and link.

**Why:** A rewrite cannot reliably distinguish binding contracts from abandoned
exploration.

**Verification:** Compare status claims against live commands, GitHub visibility,
the verification matrix and current issues.

### L1 — Historical evidence dominates repository navigation  `🟡 low · L · CONFIRMED`

**Current:** Of 1,111 tracked files, 508 live under proof, test, scripts,
experiments and benchmarks. The tree has 414 Go files, 77 Python files, 205 JSON
files and 13 command directories. Much of this is required reproducible evidence,
so bulk alone is not dead code.

**Proposed:** Preserve fixtures consumed by tests under `testdata`; move historical
receipts to a tag/archive or release artifacts after a consumer/coverage map;
remove replaced helpers only after equivalence is proven.

**Why:** The filesystem presents the evidence laboratory as if it were the active
product architecture.

**Verification:** Re-run reference searches for every candidate and prove retained
Go tests cover each removed assertion before deletion.
