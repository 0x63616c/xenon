02 · Non-negotiable behavior

The hidden contracts

These are the details a visually cleaner rewrite could accidentally destroy. Each becomes an explicit compatibility test.

1

Product

One Go binary and endpoint; every ready node accepts full operations; owners execute locally and other nodes forward once; direct S3 durability; disposable disks.

2

Registry

Opaque key-scoped CAS versions prevent ABA. Preserve canonical envelopes, transition validation and unknown-outcome behavior after dispatch.

3

Layout and authority

Populated layout is immutable. Slot order and digest are durable. Assignment is intent; generation, reservation and readiness establish authority.

4

Durability

SlateDB Commit submits work; AwaitDurable acknowledges it. Cancellation does not roll back. Whole operations pass admission or fail together.

5

Replay

Stable operation ID plus digest; persisted outcomes/count/usage/barriers; an exact replay returns the same durable result; a mismatched digest is rejected.

6

Routing

Resolve the full owner tuple, bound hops and owner attempts, preserve request identity and deadline, refresh stale routes, and let unknown result dominate.

7

Temporal

Keep protobuf field numbers, oneofs, typed errors, mutable outputs, pagination semantics, visibility behavior and history prewrite ordering.

8

Proof

DST checkers remain independent. Triangulate normative invariants, a deliberately broken mutant, and old or upstream behavior.

05 · Go-first proof

Fast at the bottom, real at the top

Authored scenarios are Go code. JSON is only a generated, stable replay artifact. MinIO and full processes are reserved for the few boundaries that need them.

Release qualificationreal S3 · Omes · soak · capacity

Ordinary Go tests + DSTthousands of virtual schedules and faults in seconds
DST loop

Search → replay → minimize

A seed generates a deterministic execution. Failure writes a stable artifact. Replay reproduces its fingerprint. Minimize removes irrelevant operations while preserving the same failure.

Bail early

Failure is the output

Stop a run on the first invariant violation, retain the seed, trace, source revision and config hash, and make the smallest reproducer a normal Go regression test.

07 · Safe replacement

Migration sequence

Each phase leaves a runnable vertical system and has a gate. The old runtime stays available as the executable reference until cutover.

0 · Freeze the reference

Tag exact source; capture golden wire, durable and behavioral corpus.

1 · Clean vertical slice

One node owns the existing full layout: CLI, process, transport, SlateDB/MinIO, embedded Temporal and a compact workflow.

2 · Deterministic control

The same pure reactor runs with real and virtual drivers; DST proves election, movement, crash and ABA cases.

3 · Horizontal operation

Three nodes, one-hop forwarding, versioned authority snapshots, fencing and unknown-result replay.

4 · Temporal compatibility

Port every typed persistence family and pass the exhaustive manifest plus upstream behavior.

5 · Operations and replacement proof

Readiness, logs, metrics, packaging and three clean-checkout journeys establish replacement-ready.

6 · Cutover

Offline migration to a protected destination prefix; revoke the old identity; crash-resume; then replace main. Real AWS remains a separate release-ready gate.

08 · Machine-checkable exit

Replacement gates

These boxes are a reading aid and persist only in this browser. The authoritative gates belong in committed tests and CI.

Replacement-ready means every gate except live AWS release qualification is green. Release-ready additionally requires the live AWS evidence.

Stop and reassess

If the first slice invents a new durable format, weakens typed errors, needs a second authority, duplicates production predicates, imports most of the old runtime through shims, or is not materially easier to understand.
