# Workflow mutable-state contract (bounded component)

Issue #45 implements nine low-level operations, without claiming the complete Temporal ExecutionStore or a working Temporal deployment. Source pin: Temporal v1.31.2, `19a774302c613da9adc4436ab14278ccdca8e0a5`.

Implemented component: CreateWorkflowExecution, UpdateWorkflowExecution, ConflictResolveWorkflowExecution, SetWorkflowExecution, GetWorkflowExecution, GetCurrentExecution, DeleteWorkflowExecution, DeleteCurrentWorkflowExecution, ListConcreteExecutions. Tasks supplied by snapshots/mutations are inserted atomically, not discarded. Task reads, completion and DLQ are a separate component. No unfinished interface methods return placeholder success.

Create checks its current pointer joined to the referenced execution row, including that row's LastWriteVersion. BrandNew rejects an existing current run; UpdateCurrent requires the expected previous completed run and version; BypassCurrent rejects the same current run. Updates support UpdateCurrent, BypassCurrent and IgnoreCurrent. ConflictResolve supports UpdateCurrent and BypassCurrent. Shard range is checked in every mutable-state create/update/reset/set transaction. Deletes deliberately do not introduce a range requirement absent from the API.

State version conditions compare stored DBRecordVersion to requested version minus one, or stored NextEventID to Condition when the requested DB version is zero. Missing mutable state has ConditionFailed; stale state has WorkflowConditionFailed with actual version/event ID. Missing current rows during UpdateCurrent update/conflict resolution return Unavailable, matching the SQL assertion helper; Create UpdateCurrent retains its separate CurrentWorkflowConditionFailed behavior. UpdateCurrent compares new-run namespace UUID values, while BypassCurrent/IgnoreCurrent impose no extra namespace guard. Current conflicts preserve run, state, status, request IDs, last-write version and optional start time. Request IDs come from the explicitly provided current-state blob as in SQL. GetCurrent returns the pinned narrow execution-state shape.

A workflow record stores the full map state in one protobuf value. Snapshot reset replaces maps; mutation applies upserts before deletes, buffers append after optional clear, and CHASM opaque data remains lossless. Execution-state storage follows SQL's serialized concrete state, while the separately supplied blob is preserved for current-row semantics. Info and map blobs remain opaque. A logical failure aborts the native transaction before the typed outcome is journaled in a new transaction under the same owner gate. Thus current pointer and earlier task inserts cannot leak through a later condition or duplicate failure.

History prewrites run in the pinned per-operation order before starting the mutable-state journal transaction. Each has a deterministic child identity. The root journal is checked first: completed root replay skips all history writes, including after subsequent deletion. A later mutable-state failure does not remove already durable history. This is deliberate upstream ordering, not a claimed cross-transaction atomic operation.

Task keys are `v1/history-task/<type>/<shard decimal width10>/<category decimal width10>/...`. Immediate suffix: signed-order task ID as 16 hexadecimal digits (sign bit flipped). Scheduled suffix: signed-order Unix seconds, 8-digit hexadecimal nonnegative nanos truncated to microseconds, signed-order task ID. Values are ExecutionTask protobufs, with the same normalized timestamp and opaque HistoryBlob. Type1 is immediate; type2 scheduled. Equal timestamps with different task IDs coexist; exact-key duplicates abort the complete transaction. Unknown task category types return Internal. Separate type prefixes preserve the separate SQL immediate/scheduled domains. Task retrieval must normalize query/completion boundaries to the same microsecond precision.

Explicit extensions and limits: pinned SQL ListConcreteExecutions returns Unimplemented; this component instead provides a real ordered live scan of one configured logical partition, with a shard-bound cursor. Global routing/fanout remains pending. Checksum and CHASM state are retained in the single record; deletion clears that record completely rather than leaving map-table orphans. The request transport ceiling remains 2 MiB, full stored image ceiling 2 MiB, and page response ceiling 3 MiB. These are fail-closed baseline ceilings, not a claim to accept every Temporal dynamic size configuration. Journal retention remains bounded without unsafe expiry.

The committed manifest and fixtures distinguish executed memory-object-store proof from the remaining S3/process, full-factory, routing, Omes and deployment gates.
