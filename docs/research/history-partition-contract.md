# History partition placement and global listing

Issue #62 distributes history shards across a fixed ordered `historyPartitions` list. The proof uses `[history-0, history-1, history-2, history-3]`. Nonnegative `ShardID % len(list)` selects the same logical partition for shard ownership, mutable state, history, history tasks and replication DLQ. Negative shards fail explicitly. Constructor input is copied; callers cannot mutate existing placement. Names/count/order are durable deployment configuration and immutable for the dataset; node addition moves these existing partitions without changing placement. Repartitioning requires a separate migration and is not silently supported.

Temporal's pinned `GetAllHistoryTreeBranchesRequest` has no shard selector. Its interface promises a maximum page size and opaque continuation, not a global ordering or snapshot. Xenon scans partitions sequentially, returning one nonempty local page at a time (possibly below requested count). Empty exhausted partitions are skipped within one invocation deadline. Local tokens remain opaque inside a versioned global token binding a SHA256 of the JSON-encoded ordered partition list, partition index, and local token. Changed lists or invalid indexes are rejected. Failed partitions are never skipped or returned as successful empty pages. The global token is only returned after a successful local result. The whole response remains bounded by one local 3MiB result. This is live pagination, not a distributed snapshot; concurrent insertion before the cursor may not appear, as with ordinary live keyset scans.

The fixed count limits independent history ownership domains to the number of configured partitions. This enables node addition and whole-partition movement while preserving every shard transaction domain; it is not unlimited scale-out or automatic repartitioning.

Run `python3 scripts/prove.py go-history-routing` from a clean committed checkout. Its five registered commands build the pinned native library/Go binary, exercise four real native owners through gRPC, verify factory configuration, and assert one unchanged deadline across empty-partition fanout. IDs, three populated/one empty partition, 1MiB branch blobs, list mutations and deadlines are committed test inputs. The shared runner binds source, manifests, tools and binary hashes and cannot pass a dirty proof. Memory-component evidence is distinct from process/S3 ownership movement and full Temporal/Omes acceptance.
