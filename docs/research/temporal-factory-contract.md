# Temporal factory integration

Temporal v1.31.2 exposes WithCustomDataStoreFactory. Xenon implements its AbstractDataStoreFactory and all nine DataStoreFactory constructors, including fair matching and the composed execution store. Options address, matchingPartition and globalPartition are strict strings; historyPartitions is a nonempty ordered list of unique strings. History uses immutable shard-ID modulo placement across that list; see history-partition-contract.md. Name must be xenon. Invalid configuration fails store creation; there is no SQL or in-memory fallback. Factory shutdown closes its connections and rejects new stores, without closing node engines or changing durable state.

Delegated agent decision: history shards and their generated tasks route across a fixed ordered history partition list. Matching queues and namespace-wide user-data batches remain colocated, as do global catalogs/queues. All domains can move independently through the S3 directory. The committed four-owner history proof verifies deterministic routing and global listing; full scalability acceptance still requires node addition and movement during the actual Temporal workload. The list must not be reordered or resized for an existing dataset without a separate migration.

The address is a stable service ingress. A single directly configured node address does not provide ingress failover. The ministack must expose a live load balancer or Kubernetes Service for node-crash tests. Node ownership remains independent of Temporal process membership.

Run python3 scripts/prove.py go-runtime-stores from a clean checkout. This unions the preceding persistence proofs with execution, fair matching and actual factory-created gRPC adapters. The factory test uses three separate native memory object-store databases and verifies configured routing, fair/legacy isolation, factory closure, persistence after reconnection and invalid options. This is not full Temporal boot or real S3 evidence. Visibility uses Temporal's separate custom visibility factory and remains an integration dependency.
