# Existing-stack Omes runner

`python3 scripts/omes_workloads.py --stage simple --profile without-faults --evidence-dir .local/evidence/full-simple --omes-binary .local/bin/omes --omes-source .local/omes-source` consumes the frozen full profile. Stages are simple, mixed and fuzz; profiles are without-faults and with-declared-faults. The controller owns stack readiness, Nexus endpoint, concurrent fault scheduling, metrics, visibility and final workload/history oracles. The runner never starts another stack or injects faults, and reports `full_acceptance:false` even after all commands exit successfully.

Reuse the controller's exact clean Omes checkout and build: `go build -o <absolute binary> ./cmd/omes` from the pinned source, without trimpath because upstream runtime.Caller locates workers. Then `omes prepare-worker --language go --version v1.48.0 --dir-name prepared`. The runner validates CLI VCS metadata, hashes the CLI and complete prepared tree, and verifies prepared/program actually depends on SDK v1.48.0 without module replacement. Exact hashes are rechecked before every invocation and afterward; all20immutable corpus binaries are checked by size/hash.

The full commands now explicitly include `--dir-name prepared`. Without it upstream workerctl/run.go builds a fresh temporary worker, making prepared-tree hashes unrelated to the executable used. This is a prospective provenance correction, not a reinterpretation of earlier runs. The existing smoke already supplied the flag. Counts and deadlines are unchanged.

Commands run from Xenon root so committed corpus paths resolve. Only argv[0] becomes the verified absolute CLI path. Each command has a900-second outer bound; mixed/fuzz retain their declared internal900-second timeout, and the controller remains responsible for overall/fault-window budgets. Raw stdout/stderr go directly to exclusive log files, with exit status, timeout, monotonic elapsed time and hash retained in result.json. Process groups are killed on interruption/timeout and after command exit to stop orphaned workers. Any command or changed-input failure returns nonzero. The evidence directory must be new, and runtime source must be clean.

`python3 -m unittest discover -s scripts -p 'test_omes_workloads.py'` runs local process controls for success, exit7, timeout and changed saved bytes. These controls are not Omes execution. No live workload has been launched by this slice; the active ministack was not available for independent use. Foundation will invoke the runner only after smoke readiness and with its own fault/measurement supervision.
