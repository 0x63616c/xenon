# Optional adapter registration observer

Issue #73, component only. `python3 scripts/prove.py recorder-adapter` executes the committed controls from a clean checkout. All twelve adapter helper invoke functions use BeginObserved before serialization or Execute. With no recorder settings, the prior default and optional asynchronous trace behavior remain unchanged.

Opt in with XENON_RPC_RECORDER_URL (numeric HTTP loopback origin), XENON_RPC_RECORDER_PRODUCER (unique actual process incarnation), and XENON_RPC_RECORDER_PHASE (controller's already-open fixed phase). XENON_RPC_TRACE_PATH is mutually exclusive. This slice does not open phases, change a running producer's phase, close the recorder, or edit the runtime controller. A future controller must supply exact process identities, open/close phases, record independently observed deaths and classify errors. rpctrace.Close checks active work and sticky observer failure, not external recorder finalization.

Registration is serialized per producer, including its acknowledgment, so concurrency cannot deliver sequence N+1 ahead of N. Each registration and terminal has a two-second total HTTP deadline and at most two identical deliveries; each HTTP attempt has a one-second client timeout. An uncertain ACK retry uses the same event identity and immutable fields. No unacknowledged invocation or Execute starts. Failure poisons the observer, propagates a typed Unavailable and prevents subsequent Execute admission. A terminal delivery failure may occur after real application work completed; it is an unknown proof outcome, not rollback. Normal Temporal retry/error semantics remain applicable and the controller must fail the measurement run.

Monotonic helper timing begins before registration wait and includes handshake overhead, serialization, Execute observations and adapter backoff. Each Execute starts its own timer before registration. Terminal records separately expose handshake_ns and duration_ns; terminal delivery/flush is excluded from that record's duration, but attempt terminal delivery is naturally inside the containing helper. RPC result_status is separate from terminal classification. These are helper RPC invocations and generated Execute calls, not complete public persistence API invocations or individual network attempts. Default 30-second adapter operation limits are unchanged; explicit observer registration and terminal reporting can add bounded instrumentation time outside those limits. This cost is included in helper observations where specified, not hidden as application speed.

Actual loopback controls delay registration and a real handler, discard the first accepted ACK, exercise two handler errors/backoff, and close the recorder listener after helper registration before Execute. The latter asserts zero backend calls, a failed observer, and no complete journal. Separate recorder controls cover actual process SIGKILL. Twenty concurrent helpers test sequence serialization. No real Temporal/Omes run or full shipping gate is claimed.
