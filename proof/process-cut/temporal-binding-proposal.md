# Proposed real Temporal mutation binding

Status: proposal for coordinator adjudication, independently challenged by the priority advocate. This is not an executed Temporal fault proof. The existing exact-selector component remains unchanged.

The adapter's `UpdateWorkflowExecution` constructs an execution UPDATE whose identity is in `Command.Mutation.Upsert.NamespaceId`, `WorkflowId`, and `RunId`; the command's top-level identity fields are not populated for UPDATE. The server validates the command and deterministic digest before Owner.Run. The journal applies the operation and stages its outcome before committing. These are the appropriate identity and candidate boundaries.

A separate optional discovery mode starts idle and unarmed with a fresh boot incarnation. The runtime controller starts a known workflow, waits for its declared ready-to-receive-signal/update barrier, obtains the actual SDK RunID, and installs an exact namespace UUID/workflow ID/run UUID watch bound to the live boot and session. The controller then triggers a real signal or update. UUIDs compare canonically; workflow IDs compare exactly. No background read, other run, CREATE, failed conditional update, or saved-outcome replay is eligible.

The first successful matching execution UPDATE becomes a candidate only after its apply and journal staging succeed and before native Commit. It holds the existing owner gate and transaction. Metadata exposes its actual operation ID, command digest, partition, family, mutation kind, workflow identity, session and boot incarnation. It exposes no payload. A bounded ARM command must echo the complete candidate identity. Its atomic transition releases this same candidate into the already selected real commit-before-await, after-await, or before-result stage. There is no arbitrary resume command, generated success, or automatic second candidate.

ARM and candidate timeout serialize through one controller lock. An expired candidate cannot subsequently arm. Timeout aborts the uncommitted transaction, quarantines the owner, and releases resources using the existing native lifecycle. No WriteHandle exists before Commit. Once Commit begins, the existing retained-handle timeout rules remain mandatory. Independent history prewrites may already have committed before this root mutation candidate; abort must not be described as zero application changes.

Acceptance must execute a real Temporal adapter mutation and prove the observed candidate corresponds to the known run, ARM reaches the declared native cut stage, and the controller SIGKILLs the exact reported process incarnation. It must preserve raw durable journal/mutable-state inspection where applicable, exact retry behavior, and workflow history/state reconciliation. Controls cover other run/namespace/workflow, reads, logical failure, replay, stale boot, changed candidate digest, duplicate ARM, ARM-after-timeout, missing hit and retained native wait. A completed SDK call alone cannot prove the targeted mutation was cut.

The controller must register the watch only after initial workflow readiness, then trigger a deliberate new operation; otherwise an early background mutation could legitimately match the same run. Binding to exact RunID deliberately excludes a Continue-As-New successor, which requires its own declared watch. Full frozen fault schedule integration remains a subsequent executed gate.
