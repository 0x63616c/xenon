# Saved Omes fuzz inputs

Twenty actual protobuf binaries were produced by the unmodified upstream kitchen-sink-gen at Omes `c6978ba39aa03551ce28974117e8d7ecf983d2b3`. `manifest.json` records each actual binary hash, size, seed, decoded-output hash, generator/source lock hashes and the complete configuration hash. Generation executes no Temporal workloads. Every emitted binary was decoded with the exact pinned kitchen-sink schema and its API submodule `d96bd55e87799e9f6a33a1c40a56cfa932566bdf`.

Run `python3 scripts/omes-corpus.py verify` from a clean checkout for a machine-readable corpus-integrity verdict. This checks all twenty immutable files and the exact replay command profile, including each input hash; it does **not** claim workflow execution, replay success, feature coverage, fault recovery or acknowledged-write preservation. Save stdout with the enclosing acceptance run manifest. The normal verifier never regenerates or overwrites input bytes.

`python3 scripts/omes-corpus.py generate` is the committed original generation command. It refuses to replace an existing manifest. For a deliberate new corpus revision, use an isolated checkout with a new corpus location and review the entire replacement. It clones the exact upstream revision, initializes the pinned API submodule, installs protoc-gen-go v1.31.0, and builds Cargo with `--locked`. The temporary source is outside Xenon's Cargo workspace: the upstream build also regenerates language bindings, so those changes are confined to disposable scratch. The original corpus was generated on macOS arm64 with Go 1.27.1, Rust 1.94.0 and protoc 36.0. New generation checks tool versions independently of GOOS/GOARCH and records its actual platform; Linux generation is supported by the command but has not been executed here. Corpus verification is platform independent. This is a Xenon generator profile, not a claim to use upstream mise's protoc 25.1.

Seeds are provenance, not replay inputs. Upstream uses Rust HashMaps for protobuf maps, so byte-identical regeneration is not assumed; replay always uses the saved bytes and hashes. Fixed inputs do not make runtime concurrency scheduling deterministic. All action probabilities retain upstream defaults, including Nexus, children and search attributes. The bounded configuration reduces action counts and timer durations; the corpus is not evidence that every required feature was selected or executed. The acceptance controller must collect actual histories and verify feature coverage separately.
