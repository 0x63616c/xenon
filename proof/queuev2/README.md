# QueueV2 proof

Run `python3 scripts/prove.py go-queuev2` from a clean checkout with the pinned toolchain. The runner builds the exact official SlateDB native library and Go node, runs the exported Temporal v1.31.2 QueueV2 interface suite over real gRPC, and exercises the committed recovery/deletion fixtures. Inputs and native/source/binary hashes are recorded in a machine report. Dirty runs never establish proof.

The upstream suite also exercises HistoryTaskQueueManager behavior, and imports Temporal test utilities; its additional pinned Go dependencies are test requirements, not alternate application storage. No upstream suite is copied or replaced by an approximate local implementation. The test server lives in the test process and uses actual gRPC and SlateDB memory object storage. It deliberately drops a completed enqueue response and requires that fault to be observed.

QueueV2 is independent from legacy Queue: named/type queue creation is mandatory; initial message ID is zero; metadata tracks the logical minimum; inclusive range deletion retains the final physical message while advancing the logical minimum. ListQueues returns live offset pagination, count and last message ID; any nonempty result has a continuation token. Reads use the exact pinned protobuf token encoding, including its ignored prefix byte, and any nonempty result has continuation. A page can be shorter than requested to fit the complete 3 MiB wire-result budget. Payloads are capped at 1 MiB; names at 1024 UTF-8 bytes. Queue identity keys include type and the hex-encoded complete name, avoiding separator collisions.

Delegated correction: pinned SQL's cursor helper ignores logical minimum when a token is present, exposing the retained deleted sentinel through an old token. Xenon clamps cursor advancement to the logical minimum; a MaxInt64 cursor returns empty without overflow. Allocation stops at MaxInt64-1 so the logical minimum remains representable after deleting the terminal message. These corrections preserve logical deletion and are tested explicitly. Empty never-used queues return a non-nil zero-deleted response instead of pinned SQL's nil response. There is no migration from SQL storage in this slice.

Creation, enqueue, range deletion and all read outcomes share the same admitted native transaction and durable replay journal. Outcome field 10 is reserved for QueueV2; existing fields are unchanged. Logical errors preserve Temporal sentinel/type identity. Replayed range deletion does not delete later messages or advance metadata twice. Unknown native outcomes quarantine the owner; replay on a fenced engine fails.

This proof is not real-S3 or process-crash validation, distributed forwarding, ownership movement, full Temporal boot or a general migration guarantee. Those remain shipping gates.
