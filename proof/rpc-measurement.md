# Optional helper RPC timing

Set `XENON_RPC_TRACE_PATH` to a unique new file for each Temporal process. Tracing is disabled by default. The first helper creates the file exclusively with mode0600; setup failure refuses operation startup. Each helper records from before serialization/deadline setup through final result and all adapter retries/backoff. Its gRPC client interceptor records individual Execute attempts with the same invocation ID, operation ID, family/method and partition. Durations use monotonic time; UTC start timestamps correlate declared fault windows. No request/response payload or error text is recorded.

`rpc_invocation` means one helper operation, not an entire public persistence method. GetOrCreateShard may invoke GET and CREATE; visibility may issue schema plus multiple partition calls; execution may stage history. Whole public API timing and outer Temporal retries remain separate measurements. Attempt status is the transport code; final invocation status includes logical error mapping. Do not treat dispatch counters or sum-of-attempt durations as invocation latency.

One65536-event queue bounds pending memory and never blocks an adapter call on disk IO. Overflow or writer failure marks the sink incomplete. After stopping server/application operations, call `rpctrace.Close(ctx)` with a bounded shutdown context and fail telemetry if it errors. A successful final `trace_end` with status `true` is mandatory; `trace_error`, false footer, missing footer, malformed/truncated data or unmatched attempts are incomplete evidence. SIGKILL may lose queued events and necessarily lacks a complete footer; explicitly label that process's telemetry incomplete, never claim complete fault-window measurements from it. No silent dropped-event success is permitted.

Run `python3 scripts/prove.py rpc-measurement` from a clean checkout. Three registered race tests cover actual loopback retry/backoff timing, bounded queue overflow and write errors. They do not run the ministack or alter production deadlines. Controller opt-in, graceful close and artifact validation must be integrated before acceptance latency gates use this data.
