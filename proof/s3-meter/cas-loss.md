# Lost conditional directory response

The existing loopback S3 proxy has an optional `--cas-loss-evidence <new-file>` mode. Default behavior is unchanged. POST one bounded selector to its existing report listener at `/cas-loss/arm`: exact escaped directory path, partition, node and boot incarnation. The selector expires after120s and cannot be rearmed. Only a matching opening record PUT with If-Match can be selected. Unknown/chunked content framing fails the hook; it is never guessed or rewritten.

The proxy forwards the actual signed request without modifying Host, URI or bytes. After real upstream2xx and ETag, it synchronizes metadata/hash receipt and aborts the HTTP connection before sending response headers. It subsequently records an exact GET body digest match and the same transition/generation reaching READY. The separate `--validate-cas-loss <journal>` command validates bounded canonical receipts. Payloads and authorization headers are never recorded.

`python3 scripts/prove.py cas-loss` runs HTTP controls and an actual signed MinIO Directory.Reserve/Ready test with production AWS SDK checksum and retry defaults. MinIO execution must occur in its reserved isolated port19009 slot. SDK retry may yield412 on the original If-Match, followed by Directory.publish's exact fresh GET reconciliation. A missing hit, successful-upstream evidence, matching GET or READY fails. This component is not proof that a new runtime owner served workload; that requires actual movement and incarnation-bound dispatch counters in the runtime controller. Intentional response abort is never counted as normally completed HTTP traffic.
